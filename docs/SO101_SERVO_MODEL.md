# SO-101 Web シミュレータのサーボモデル

2026-10-26。入口: http://localhost:8025/ 。実機通信は行わない。

6 台の STS3215 を独立した電気・熱・位置制御モデルとして計算する。
同じ品番なので初期定数は同じ。姿勢による重力と慣性が異なるため、各軸の電流・速度・温度は異なる。
熱抵抗と熱容量は UI で個体ごとに変更できる。乱数による個体差は付けない。

## 時間と熱

物理時間の刻みは 1 ms。熱と保護タイマーも同じ物理時間で更新する。
一時停止中は時間が進まない。再生倍率は壁時計に対する目標倍率であり、CPUが追いつかないときは遅くなる。
計算していない時間を経過したことにはしない。姿勢指令・荷物・周囲温度・熱設定を変えても熱履歴は消さない。
初期化ボタンは温度と履歴も初期化し、周囲温度の冷間状態からやり直す。

熱は内部センサ温度の代理となる1節点のモデル。巻線温度や筐体表面温度の実測再現ではない。

    Rcu(T) = 1 Ω × [1 + 0.00393 × (T − 25℃)]
    発熱 P = I² Rcu(T)
    放熱 Q = (T − 周囲温度) / Rth
    Cth × dT/dt = P − Q

電流を一定とする1刻み内で解析積分し、熱損失エネルギーも積算する。
発熱は電流の2乗に比例する。脱力すると発熱が止まり、時定数 Rth×Cth で周囲温度へ近づく。
周囲のほうが暖かいときは放熱が負になり、環境から暖められる。
ギア・ドライバの発熱、巻線と筐体間の遅れ、空気の流れ、隣接サーボからの伝熱は同定していない。
以前のモデルは熱計算にも4.44 Ωを使っていた。今回1 Ωへ分離したため、以前の温度結果とは一致しない。
仮の熱定数を過去の温度観測へ合わせ直したとは主張しない。

温度の予測グラフは現在の発熱 P を固定した次の解析解。

    T∞ = 周囲温度 + P × Rth
    T(t) = T∞ + [現在温度 − T∞] × exp(−t / (Rth×Cth))

「脱力」の線はP=0。同じ軸に描く実線の過去履歴は実際の積分結果。
未来は条件付きの予測で、過負荷や過電流による停止後の動作を含まない。
70℃への到達時間はこの条件下の値。到達しない場合も、実機の安全や永久運転を保証しない。

## 速度・力・機械

    I = [duty × 電圧 − Ke × 角速度] / Req(T)
    電磁トルク = Kt × I

Reqにも同じ温度係数を使う推定により、温度が上がると停止時の最大トルクが下がる。
逆起電力により、回転が速いほど同じ方向へ加速するためのトルクが減る。
速度対トルクの帯は駆動出力の上下限。過負荷保護・トルク設定・過熱停止で幅が変わる。
摩擦と指令速度の上限は別に計算する。表示するトルクは減速機出力軸の等価電磁トルクで、接触力ではない。
「熱平衡の目安」は70℃での定常銅損から求める値で、メーカーの連続定格ではない。
過負荷・過電流・ギア強度などの限界を含まない。

MuJoCo は元モデルの質量・慣性・可動範囲・摩擦・重力を計算する。
Web版の荷物はTCPの点質量としてグリッパの質量・重心・慣性に合成する。荷物の重力を別途加えて二重計上しない。
荷物変更は姿勢・速度・時刻を保持し、付け替え時の衝突や運動量交換は計算しない。
床接触は既存のばね・ダンパモデル。自己接触・歯車のバックラッシュ・破損は未実装。

## API

- `GET /api/state?since=...&since_thermal=...`: 各軸の `regs`、`physics`、物理時刻、温度履歴を返す。
- `GET /api/analysis?joint=elbow_flex`: 選択軸の速度対トルク帯と、600秒の条件付き熱予測。
- `POST /api/cmd` の `op=regs` に `joint` を添えると選択軸だけ設定。省略は全軸。
- `op=motor, joint=..., params={r_th,c_th}`: 個体の熱定数を設定。
- `op=world, ambient_c=...`: 全軸の周囲温度を変更。`payload_kg` と `floor` は従来どおり。
