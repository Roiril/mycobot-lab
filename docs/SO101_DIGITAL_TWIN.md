# SO-101 の動作設計と実機追従

## 使う場面

「動きを作る」では、相手へ向く姿勢や返答を待つ間を仮想アームで試す。目標姿勢を順に追加し、各姿勢への移動時間と到着後の待機時間を編集する。姿勢列を保存すると、同じ指令を再生・比較できる。

「実機で試す」では、先に実機の角度を観測する。「実機姿勢を仮想へ」で仮想の開始姿勢を合わせる。周囲と台座を確認して「実機を追従させる」を押すと、その画面の目標姿勢が実機にも送られる。保存済みの動作も同じ経路で再生できる。

## 要件と実装した振る舞い

| 要件 | 振る舞い・受入条件 |
|---|---|
| 実機がなくても設計できる | 既定の `--hardware off` で物理予測・編集・保存・再生を使用できる |
| 動作意図を保存する | version 1 JSON に名前・6軸の角度・移動秒・待機秒を保存する。観測履歴は動作として保存しない |
| 動作を調整できる | 姿勢を追加・並べ替え・削除できる。姿勢を呼び出して調整し、追加し直せる |
| 読み取りと駆動を分ける | 接続・観測・仮想への姿勢取込では、実機レジスタへ書き込まない |
| 接続時に急に動かない | 全軸の新しい計測・校正照合・静止・目標との差3°以内を追従開始条件にする |
| 指令と予測と実測を区別する | 指令は橙。仮想の予測は不透明なアーム。実測は青い線で重ねる。各軸の目標との差も表示する |
| 実機へ送る動作を固定する | 実機追従中の姿勢列再生は保存済み版だけ。再生中の編集は拒否する |
| 実機を低速で試せる | 追従の上限は15°/s。保存動作も全ステップを事前検査し、時間が短すぎる動作を拒否する |
| 操作する画面を一つにする | 追従を開始した画面が期限付きの制御権を持つ。他の画面からは目標変更できず、停止はできる |
| 通信断で勝手に再開しない | heartbeat の1秒期限で追従を解除する。再接続・再読込・異常復旧による自動再開はしない |
| 停止と脱力を区別する | 常設停止と Esc は追従・姿勢列の再生を止める。実機を脱力させない。仮想脱力は別ボタン |

## 起動

既存シミュレータと同じページ・ポートを使う。追加のライブラリは不要。

```powershell
# 仮想で動作を設計
.venv-so101\Scripts\python.exe scripts/so101_sim_server.py
# 模擬実機で接続・追従・停止を試す（serialを開かない）
.venv-so101\Scripts\python.exe scripts/so101_sim_server.py --hardware mock
# SO-101 follower単体と接続できる状態にする（起動だけでは接続しない）
.venv-so101\Scripts\python.exe scripts/so101_sim_server.py --hardware real
```

画面は `http://localhost:8025/`。実機連携は loopback に限る。CH343 と電圧で follower を識別する。曖昧な場合や別プロセスによる COM 占有時は接続を拒否し、他のプロセスを止めない。必要なら `--hardware-port COM番号` で候補を絞れる。

実機の使用前に、同じ follower を使う cockpit・統合サーバ・校正ツールの接続を終了する。実機への接続は「接続して観測」で行う。実機モードを有効にするための再起動と、画面上の接続は別の操作である。

## 動きを設計する手順

1. 仮想のダイヤルか名前付き姿勢で、動作の最初の目標姿勢を作る。
2. 「現在の目標姿勢を追加」で姿勢列へ加える。
3. 次の姿勢を作って追加する。移動時間と待機時間を調整する。
4. 「仮想再生」で順序と間を確認する。重さやサーボ設定による予測の変化も見られる。
5. 名前を付けて保存する。JSON の書出・読込で別の環境へ渡せる。

最大200姿勢・合計600秒。仮想のスロー再生は設計時に使う。実機追従の開始時は1×・一時停止解除が必要で、追従中は物理設定の変更を拒否する。

## 実機で確かめる手順

1. 「実機で試す」へ切り替えて「接続して観測」を押す。模擬実機か実機かを接続先表示で確認する。
2. 校正と通信鮮度を確認し、「実機姿勢を仮想へ」を押す。実機は動かず、仮想の姿勢が更新される。
3. 台座の固定・周囲の空き・停止手段を確認して、チェックを入れる。
4. 「実機を追従させる」を押す。現在位置を目標へ設定してから必要な関節のトルクを有効にする。
5. 目標を少し変えるか、保存済み動作を再生する。物理予測と実測のずれを確認する。
6. 常設停止か Esc で止める。画面を離れる場合も追従を解除する。切断は HOME や脱力を実行しない。

## 内部の責務

- `twin_studio.py` は動作形式・永続化・補間・再生を担当する。物理時刻に沿って目標を生成し、仮想と実機へ同じ目標を配る。
- `so101_sim_server.py` は既存の1kHz物理積分と HTTP を担当する。ブラウザの描画や polling が止まっても、追従の監視を省略しない。
- `twin_link.py` の単一 worker が実機 I/O を所有する。既存 `RawFeetechIO` と `FollowerGovernor` を使用し、観測・追従・停止を分ける。自動冷却移動は行わない。
- 実機 worker は25Hzを目安に動作する。I/O に期限を設けるが実時間制御の保証はない。状態取得はキャッシュを読むが、進行中の I/O が保持するロックを待つ場合がある。

実機の角度変換は導入済み LeRobot の `DEGREES` に合わせ、`(raw - range_mid) * 360 / 4095` とする。全6軸とも角度で扱う。グリッパの0〜100正規化値を混ぜない。Homing_Offset は firmware が適用済みなので二重に引かない。校正欠落時の全域への代替は認めない。[LeRobot の校正手順](https://huggingface.co/docs/lerobot/so101)も参照。

校正ファイルは `~/.cache/huggingface/lerobot/calibration/robots/so_follower/so101_follower.json`。軸名・ID・範囲・offset・位置モード・解像度・速度単位を実機の値と照合する。照合できない場合は実測角度を確定せず、追従を拒否する。

## API と状態

`GET /api/twin/state` は編集対象・版番号・保存版・ライブラリ・再生位置・実機状態を返す。同じ情報を既存の `/api/state` の `twin` に含める。`measured_bodies` は新鮮で校正済みの実測値だけから計算する。

`POST /api/twin/cmd` の操作は `program / capture / save / load / play / stop / hardware_connect / hardware_disconnect / import_actual / follow / heartbeat`。`client_id` で操作する画面を識別する。`follow` 応答で制御期限更新用の lease を開始画面にだけ返す。lease は state に含めない。編集には `expected_revision` を付けられ、他画面の変更との衝突を拒否する。

状態は `disconnected → observing → following → stopped`。通信や保護の異常は `fault` へ進む。停止指令の送信成功と実測による停止確認は `stop_confirmed` で区別する。通信断時は停止確認を保証できない。

動作ファイルは `data/so101_motions/`。名前をハッシュに変換してパスを生成し、一時ファイルを検証した後に置換する。既存ファイルは置換失敗時に保持される。

## 検証と制限

実機を動かさず、校正・観測時の書込ゼロ・追従出力・全経路検査・速度制限・停止優先・制御権・通信断を模擬実機で検証する。検証コマンドは `.venv-so101\Scripts\python.exe -m unittest discover -s tests -p 'test_so101*.py' -q`。

熱モデルは未校正であり、実機の安全判断に使わない。実機の床位置と自己干渉のしきい値にも暫定値が残る。到達と動作時間は負荷や保護によって指令から遅れる場合がある。画面は位置制御のソフト停止であり、物理的な緊急停止装置ではない。

人の入力を待つ分岐やセンサによるイベント駆動は今回の姿勢列には含めない。外部アプリが追従開始後に同じ目標 API を使うための責務境界は保持している。
